# 内容迁移

把散落在各处的笔记（Markdown / 纯文本）批量转成博客文章。

## 三步走

```bash
# 1. 把笔记丢进 notes/（子目录随意，分类会跟着走）
# 2. 先干跑，看会生成什么，不落盘
node scripts/import-notes.mjs --src notes --dry-run

# 3. 确认无误再真正导入
node scripts/import-notes.mjs --src notes --category 笔记 --tag 旧文
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--src <dir>` | **必填**，笔记目录，递归扫描 `.md` / `.markdown` / `.txt` |
| `--out <dir>` | 输出目录，默认 `content/blog` |
| `--category <name>` | 统一分类；不传则取笔记所在子目录名，再退回「随笔」 |
| `--tag <a,b>` | 追加标签，逗号分隔 |
| `--date-from <mode>` | `mtime`（默认，文件修改时间）/ `filename`（从文件名解析日期）/ `frontmatter` |
| `--dry-run` | 只打印将写入的内容，不产生任何文件 |
| `--overwrite` | 目标已存在时覆盖；默认自动加 `-2`、`-3` 后缀，绝不静默覆盖 |

## 字段映射

| frontmatter | 来源（按优先级） |
| --- | --- |
| `title` | 原 frontmatter → 正文第一个 `# 标题` → 文件名（`_`/`-` 转空格） |
| `description` | 原 frontmatter → 正文第一段（跳过标题/引用/图片/代码块，截断 80 字） |
| `path` | 原 frontmatter → `/blog/<slug>`（**总是显式写入**，见下） |
| `date` | 原 frontmatter → 文件名日期 → 文件 mtime |
| `category` | 原 frontmatter → `--category` → 子目录名 → 「随笔」 |
| `tags` | 原 frontmatter + `--tag` + 子目录名 + 正文前 500 字里识别到的技术词 |
| `draft` | 原 frontmatter（默认 `false`） |

已有 frontmatter 的文件：**保留原有字段**，只补齐缺失的。

## slug 规则（重要）

文件名 → slug：空格 / 下划线转 `-`，去掉 `\ / : * ? " < > |`，合并连续 `-`，**中文保留**。

> **为什么必须显式写 `path`**：Nuxt Content 默认会对文件名做 slugify，非 ASCII 字符会被整段剥掉。
> 实测 `学习笔记-网络基础.md` 会塌成 `/blog`（直接和列表页撞路径），`带frontmatter的笔记.md` 变成 `/blog/frontmatter`。
> 所以脚本总是写入 `path: /blog/<slug>`，保证 URL 和文件名一致。

如果不想让 URL 出现中文，把源文件改成英文名再导入即可，或者手工改生成文件里的 `path`。

## 完整示例

```bash
# Windows PowerShell
node scripts/import-notes.mjs --src notes --out content/blog --category 笔记 --tag 旧文 --dry-run
node scripts/import-notes.mjs --src notes --out content/blog --category 笔记 --tag 旧文

# macOS / Linux（一样，只是路径写法不同）
node scripts/import-notes.mjs --src ~/Documents/notes --out content/blog --tag 整理
```

输出长这样：

```
成功 3 / 跳过 0 / 失败 0
  ✔ 学习笔记 网络基础.txt → content\blog\学习笔记-网络基础.md
  ✔ 2024-03-15-vue3响应式踩坑.md → content\blog\2024-03-15-vue3响应式踩坑.md
  ✔ 带frontmatter的笔记.md → content\blog\带frontmatter的笔记.md
```

## 常见问题

**Q：重复导入会不会覆盖我的文章？**
不会。目标文件已存在时自动生成 `-2`、`-3` 后缀，除非显式加 `--overwrite`。

**Q：中文文件名有问题吗？**
脚本会显式写 `path`，URL 正常。但中文 URL 复制出来会被浏览器编码成 `%E5%AD%A6...`，观感较差；在意的话就用英文文件名。

**Q：原文件的 frontmatter 会被覆盖吗？**
不会，只补缺失字段。但 `--overwrite` 会重写整个目标文件（内容仍是「原 frontmatter + 补齐字段 + 原正文」）。

**Q：导入错了怎么回滚？**
`content/blog/` 是纯文件目录，删掉对应 `.md` 即可；源笔记在 `notes/` 里没动过。建议导入前先 `git add -A && git commit`。

**Q：`description` 提取到的不是想要的段落？**
在源文件里手动加 `description:` 到 frontmatter，脚本会优先用它。

**Q：支持嵌套目录吗？**
支持，递归扫描。分类默认取文件所在的直接子目录名，所以按目录组织笔记最省事：

```
notes/
├─ 前端/
│  └─ vue3-踩坑.md        → category: 前端
├─ 后端/
│  └─ nestjs-笔记.md      → category: 后端
└─ 随笔.txt               → category: 随笔
```
