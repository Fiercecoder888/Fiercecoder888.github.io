# 静态托管适配审计（子路径部署 / GitHub Pages 项目站）

> 本文是对 `docs/部署.md` §1.2 中「项目站的正确修法见 `docs/静态托管适配.md`」那一段的落实。
> 基础设施层面的结论（仓库没配 `app.baseURL`、工作流没传 base）见姊妹文档 `docs/静态产物验证.md` §「问题 1」；
> 本文负责**逐文件清点硬编码根路径**，并给出每一条的修法。

## 一句话结论

**用户站（仓库名 `<user>.github.io`，站点在 `/`）现状零改动即可用；项目站（站点在 `/<repo>/`）必须先把 `app.baseURL` 配起来，再改掉 54 处以 `/` 开头的硬编码路径——否则桌面图标、壁纸、RSS/Sitemap/llms.txt 入口会集体 404。**

补一句容易反直觉的：`app/assets/css/main.css` 里那 10 条 `url('/cursors/...')` **看起来是最典型的硬编码，实际是安全的**——构建时会被 Nuxt/Vite 改写成相对路径 `url(../cursors/...)`，天然与 base 无关（证据见 §4.2）。`docs/部署.md:70` 说这 10 条会坏，这一条**已证伪**，请以本文为准。

### 4.2 为什么 `main.css` 的 `url('/cursors/...')` 是安全的（与 `docs/部署.md:70` 相反）

结论不是猜的，有两条独立机制 + 产物实测：

1. **产物实测**：`dist/_nuxt/entry.Bv2SmSWs.css` 中 10 条光标全部是 `url(../cursors/*.svg|webp)`。
2. **Vite 侧机制**：CSS 里的 `url()` 若命中 `public/` 下的真实文件，会走 `checkPublicFile` → `publicFileToBuiltUrl` 变成占位符，最后经 `toOutputFilePathInCss` 落地；而 Nuxt 给 Vite 注入了 `experimental.renderBuiltUrl`，对非 JS host 明确返回相对路径：
   `@nuxt/vite-builder@4.5.2/dist/index.mjs:2600-2601` → `renderBuiltUrl: (filename, { type, hostType, ssr }) => { if (hostType !== "js") return { relative: true }; … }`
   → CSS（`hostType === 'css'`）拿到 `{ relative: true }`，由 Vite 输出成相对 CSS 文件位置的 `../cursors/...`。
3. **Nuxt 侧机制（对带引号的 url 不生效，但可作旁证）**：`@nuxt/vite-builder/dist/index.mjs:737-748` 的 `generateBundle` 会把 CSS 里的 `url(/public-asset)` 改写成相对路径。注意其正则是 `CSS_URL_RE = /url\((\/[^)]+)\)/g`（同文件 `:693`）——**要求 `(` 后紧跟 `/`，所以只匹配不带引号的 `url(/x)`**。本项目的写法是 `url('/cursors/...')`（带单引号），这条**不匹配**，真正生效的是上面第 2 条。
   ——这一点值得记下来：同一份 CSS 如果把引号去掉写成 `url(/cursors/x.svg)`，就会走第 3 条；写成 `url('/cursors/x.svg')` 走第 2 条。两条都通向相对路径，所以**带不带引号都安全**。

前提：引用的文件必须真实存在于 `public/` 下。已核对，这 10 个文件在 `public/cursors/` 中全部存在（`normal-select.svg`、`link-select.svg`、`text-select.svg`、`move.svg`、`busy.webp`、`unavailable.svg`、`diagonal-resize-1.svg`、`vertical-resize.svg`、`diagonal-resize-2.svg`、`precision-select.svg`）。任一文件缺失，就会退回「构建期不解析、运行时原样保留」从而**恢复成根绝对路径**并真的坏掉。

### 4.3 `<NuxtLink>` 和 `router.push` 自动带 base

- `<NuxtLink>` 的 href 生成：`nuxt/dist/app/components/nuxt-link.js:96` → `applyTrailingSlashBehavior(joinURL(config.app.baseURL, to.value), …)`
- `router.push` 的地址写入：`nuxt/dist/app/plugins/router.js:70` → `joinURL(baseURL, to.fullPath)`
- 命令式跳转：`nuxt/dist/app/composables/router.js:153` → `joinURL(useRuntimeConfig().app.baseURL, fullPath)`

### 4.4 `<head>` 需要手工处理（不是「Nuxt 会自动加 base」）

已核实 `nuxt@4.5.2` 与 `@unhead/vue@3.4.0` 的 head 运行时里**没有任何 `baseURL` 处理**（对 `nuxt/dist/head/**`、`nuxt/dist/app/composables/head.js`、`@unhead/vue/dist` 检索 `baseURL` 均无命中），产物 `dist/index.html` 也确认 `href="/favicon.svg"`、`href="/rss.xml"` 原样输出。所以 `nuxt.config.ts:39,40` **必须自己拼 base**。
