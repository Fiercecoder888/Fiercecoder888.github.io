# 评论系统

自建评论系统：Nitro API + SQLite（better-sqlite3）+ Vue 组件，无第三方服务、无外部依赖。

## 为什么自建

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **自建 Nitro + SQLite**（本方案） | 零外部服务、数据在自己手里、本地开发就能跑通 | 需要 Node 常驻进程（静态托管下 API 不可用） |
| Waline / Twikoo | 部署简单、有后台 | 依赖第三方服务或额外容器 |
| Supabase | 免费额度、带实时 | 需要注册与密钥管理 |

## 目录

```
server/utils/comments-db.ts          # SQLite 连接、建表、CRUD、限流
server/api/comments/index.get.ts     # GET  列表
server/api/comments/index.post.ts    # POST 发表
server/api/comments/[id].delete.ts   # DELETE 删除（需要 admin token）
app/components/BlogComments.vue      # 前端组件（客户端拉取）
```

数据库文件：`.data/comments.sqlite`（WAL 模式）。可用 `COMMENTS_DB_PATH` 环境变量覆盖路径。

## 表结构

```sql
CREATE TABLE comments (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  post_path  TEXT NOT NULL,          -- 文章路径，如 /blog/hello-blog
  author     TEXT NOT NULL,
  email      TEXT,                   -- 不返回给前端
  content    TEXT NOT NULL,
  created_at TEXT NOT NULL,          -- ISO 字符串
  status     TEXT NOT NULL DEFAULT 'approved',
  ip         TEXT,
  ua         TEXT
);
CREATE INDEX idx_comments_post_path ON comments (post_path);
```

## API

统一返回 `{ code, message, data }`。

### GET /api/comments?path=/blog/hello-blog

```powershell
Invoke-RestMethod 'http://localhost:3123/api/comments?path=/blog/hello-blog'
```

```json
{
  "code": 200,
  "message": "请求成功",
  "data": [{ "id": 1, "author": "小明", "content": "写得不错", "createdAt": "2026-09-09T12:00:00.000Z" }]
}
```

`path` 必须以 `/blog/` 开头，否则 400。最多返回 200 条，按时间升序。

### POST /api/comments

```powershell
Invoke-RestMethod -Method Post -Uri 'http://localhost:3123/api/comments' `
  -ContentType 'application/json' `
  -Body '{"path":"/blog/hello-blog","author":"小明","content":"第一条评论","email":"me@example.com"}'
```

校验规则：

| 字段 | 规则 | 失败返回 |
| --- | --- | --- |
| `path` | 必须以 `/blog/` 开头 | 400 |
| `author` | 去空白后 1–30 字符 | 400 |
| `content` | 去空白后 1–500 字符 | 400 |
| `email` | 可选，填了必须是合法邮箱 | 400 |
| `website` | **蜜罐**：填了直接返回成功但不落库 | 200（假成功） |

### DELETE /api/comments/:id

需要请求头 `x-admin-token`，值为 `NUXT_COMMENTS_ADMIN_TOKEN`（默认 `dev-admin-token`，生产环境务必改）。

```powershell
# 无 token → 401
Invoke-RestMethod -Method Delete 'http://localhost:3123/api/comments/1'

# 带 token → 200
Invoke-RestMethod -Method Delete -Uri 'http://localhost:3123/api/comments/1' `
  -Headers @{ 'x-admin-token' = 'dev-admin-token' }
```

## 防刷策略

1. **蜜罐字段** `website`：真人看不到，机器人常照填 → 静默丢弃。
2. **限流**（内存 Map，按 IP）：两次提交间隔 ≥ 10 秒；1 小时 ≤ 20 条。超限返回 429。
3. **长度校验**：昵称 30 字、内容 500 字上限。
4. 前端 `maxlength` 只是体验，**服务端校验才是防线**。

## 前端组件

`app/components/BlogComments.vue`，在文章详情页这样用：

```vue
<BlogComments :post-path="route.path" />
```

关键设计：**只在 `onMounted` 里用 `$fetch` 拉数据**（`server: false` 的等价做法）。原因是 `pnpm generate` 预渲染文章页时会执行组件 setup，如果此时发请求，静态生成会失败或写出错误内容。

## 生产部署注意

- `pnpm generate` 产出的是纯静态文件，**API 不会存在**，评论自然不可用。
- 要带评论，用 Node 模式部署：
  ```bash
  pnpm build
  NUXT_COMMENTS_ADMIN_TOKEN=你的强口令 node .output/server/index.mjs
  ```
  再用 Nginx / Caddy 反代。
- 数据库备份：直接拷 `.data/comments.sqlite`（连同 `-wal`、`-shm` 文件，或先执行一次 checkpoint）。
- 想做反代后面的 IP 限流，确保 Nginx 传 `X-Forwarded-For`，服务端已按该头的第一个值取 IP。
