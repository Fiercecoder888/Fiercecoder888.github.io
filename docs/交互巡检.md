# 交互巡检（T11）

> 巡检对象：`https://fiercecoder888.github.io/`（线上 GitHub Pages 产物）
> 巡检范围：**交互健壮性 + 窄屏 + 无 JS 降级**。T9 已覆盖的「页面里有没有代码/开发者痕迹/占位符」本次**不重复**。
> 铁律：**只查不修**。本次没有改动 `app/`、`tools/`、`server/`、`content/`、任何源码或依赖，没有 git commit/push。
> 唯一写出的仓库文件是本文档 `docs/交互巡检.md`；探针脚本与截图都在已 gitignore 的 `preview/t11/`。

## 0. 怎么复现

| 项 | 说明 |
| --- | --- |
| 浏览器 | Playwright 自带的 `chrome-headless-shell`（`%LOCALAPPDATA%\ms-playwright\chromium_headless_shell-1228\...\chrome-headless-shell.exe`），**没有安装 playwright npm 包** |
| 驱动方式 | 照抄 `tools/live-probe.mjs` 的 CDP 写法：spawn + `--remote-debugging-port=9452` + WebSocket + `Runtime.evaluate` / `Input.dispatch*` / `Page.captureScreenshot`；独立 `--user-data-dir`（不碰用户正在跑的 Chrome） |
| 探针库 | `preview/t11/cdp.mjs`（启动/点击/拖拽/双击/按键/截图/布局扫描） |
| 场景脚本 | `preview/t11/a-narrow.mjs`、`a2/a3/a4`、`b-windows.mjs`、`b2-fixups.mjs`、`c1-menu-toggles.mjs`、`c1b-control-center.mjs`、`c2-context-wallpaper.mjs`、`c3-recheck.mjs`、`c4-recheck2.mjs`、`d-nojs.mjs`、`e-input.mjs`、`e2-fixups.mjs`、`f-final.mjs`、`f2-ctx.mjs` |
| 原始读数 | 同目录 `out-*.json` + `_*.log` |
| 截图 | `preview/t11/*.png`（本文档每行都标了文件名） |
| 运行方式 | `node --use-system-ca preview/t11/<脚本>.mjs`（一次只开一个浏览器，跑完即关） |
| 窄屏方式 | `Emulation.setDeviceMetricsOverride`（`mobile:false`、DPR 1、`--hide-scrollbars`），配合站点自带的 `<meta name="viewport" content="width=device-width, initial-scale=1">`，所以视口宽 = CSS 像素宽，等价于手机宽度 |
| 无 JS 方式 | 导航**之前**调用 `Emulation.setScriptExecutionDisabled{value:true}`（不是 `--disable-javascript` 启动参数） |

**环境说明（影响读数，先声明）**：本机网络拉 `sqlite3.wasm` 实测要 **16.5 秒**（405 KB 传输量）。凡是和「客户端内容库冷启动」相关的耗时，**绝对秒数带有本机网络因素**，但「这段时间界面上有没有反馈」与网络无关，那才是缺陷本体。

## 2. 窄屏（<640px）结论

**从来没有测过，这次补上了。结论：布局本身是干净的，塌的是「桌面窗口」这一层。**

### 好的部分（实测无问题）
1. **顶栏窄态工作正常**：390 宽只剩 🍎 + 站名 + 控制中心 + 时间，四个都在视口内（最右 382 ≤ 390），菜单能点开、能 Esc 关、能滑过切换；顶栏自身 scrollWidth = clientWidth，没有溢出。唯一代价是**时钟只剩 `HH:MM`，日期完全消失**（宽态是「周四 9月10日 21:44」）。
2. **没有任何页面级横向滚动条**：`/`、`/blog/`、`/tags/`、`/about/`、文章页在 390 宽下 `documentElement.scrollWidth − clientWidth` **全部 = 0**。
3. **文章页可读**：正文 332px 宽；`pre` 代码块宽 332、内部可横滑 43px，**没有撑破布局**；能滚到文末。
4. **Launchpad 网格正常**：14 个应用在 `grid-cols-3` 下全部落进 326px 宽的网格，0 越界、0 命中失败，容器可纵向滚动；搜索框自动聚焦、输入过滤可用。
5. **Spotlight / 控制中心的几何没问题**（问题在别处，见下）。
6. **右键菜单在窄屏会正确夹取**：贴在右下角 (385,838) 右键时被夹到 (152,436)，右 360、下 780，12 项全部可点。
7. **Dock 按设计降级**：禁用放大（恒 52px），改成横向滚动。
8. **矮屏 390×640 不会压叠**：Dock 565..628 与「清空桌面」按钮 514..544 不重叠。
9. **一屏模式在窄屏可用**：内容区 720 高、可内滚 1338px，退出按钮 126×28 在 (246,45) 可点。
10. **700×900（断点之上）恢复宽态**：顶栏 13 项全回来，Dock 恢复放大（52→100px），不需要横滑。

### 坏的部分（真缺陷）
1. **【最严重】窄屏打开任何桌面窗口都严重超出屏幕，而且挪不动、滚不到。**
   - 390×844：Finder `(12,122,900×560)` 右边缘 **912**（超出 **522px**）；终端 720 宽 → 右 732；系统设置 520 宽 → 右 532；390×640 下 520 宽窗口右 532（超出 142px）。
   - 三个叠加时全部越界：`finder 12..912 / terminal 12..732 / settings 12..532`。
   - **没有出路**：① 源码在 `innerWidth<640` 时直接禁用拖拽（实测拖 250px 位移为 0）；② 窗口内容区 `scrollWidth == clientWidth == 898`，**内部没有横向滚动**；③ 窗口是 `position:fixed`，不产生页面横向滚动条（documentElement 横向溢出 0）。所以右侧 500 多像素**既看不到也滚不到**。
   - 唯一救法是点绿点最大化（`inset-2` 到视口内），但用户未必想得到。
   - **700×900 也存在**：Finder 900 宽 → 右 912，超出 212px。
2. **【中】窄屏 Dock 的 4 个图标完全在屏幕外**（settings/wallpaper/news/trash 在 x 392..640），必须横滑 Dock 才能点到；同时悬浮 tooltip 在窄屏**被裁掉**（标签在 Dock 上方 41px，而 `overflow-x:auto` 使 `overflow-y` 变 auto，`elementFromPoint` 命中的是页面正文）→ 用户既看不到图标名，也要盲滑。
3. **【低】每次加载闪一下开机画面**：已看过开机动画（或关掉该开关）时，100ms 采样仍能看到全屏黑底开机层，600ms 才消失。

### 窄屏下**没有**发现的问题（避免误伤）
- 没有元素重叠、没有被裁切的正文、没有点不到的顶栏/Launchpad/右键菜单项、没有横向滚动条、没有在 640 断点两侧的错位（700 侧全部恢复正常）。

## 3. 无 JS 降级结论

**结论：降级质量意外地好——内容 100% 可用，缺的是「一切交互」。**

- 五个 URL（`/`、`/blog/`、`/blog/hello-blog/`、`/about/`、`/tags/`）在禁用 JS 后**都不是空白**：SSR 出来的正文全文、文章卡片、标签、代码块、页脚都在（正文长度 870 / 800 / 1022 / 557 / 239 字）。
- **没有 `[data-boot-screen]`**：开机动画层在 `<ClientOnly>` 里，所以无 JS 时**不会黑屏卡死**（这是最容易被忽略的坑，本站没踩）。
- **没有**「正在加载文章…」「页面走丢了」这类只在 JS 可用时才该出现的文案——源 HTML 里根本没有这些串（我用 `Invoke-WebRequest` 直接查过）。
- 顶栏、Dock、壁纸照常渲染（`[data-topbar]` 1440×29、`[data-dock]` 640×63、`[data-wallpaper]` 1440×900），但 **27 个 button 全部无响应**：菜单点不开、Dock 点不动、右键菜单不存在、Spotlight/Launchpad/窗口层根本不在 DOM 里（`[data-spotlight] / [data-launchpad] / [data-context-menu]` 全部 count=0）。
- 可点的是**真正的链接**（28/10/13/4/16 个 `<a href>`）：文章卡片、标签、页脚 Sitemap/llms.txt/RSS、上一篇/下一篇都能正常跳转。
- 两个小瑕疵：**顶栏时钟是个空按钮**（宽 16px、文本空，因为时间只在客户端算）；**没有 `<noscript>` 提示**（不过内容不依赖 JS，所以不构成阻塞）。

### 覆盖到了
- **窄屏**：390×844、390×640、700×900 三档；顶栏窄态（4 个可见项逐个点开 + 每项命中测试）、Dock（横滑/放大禁用/悬浮标签/4 个越界图标）、Launchpad（网格/滚动/搜索框/背景点击关闭）、Spotlight、右键菜单夹取、文章页代码块与可读性、`/`、`/blog/`、`/tags/`、`/about/` 四页横向溢出扫描。
- **窗口操作**：拖拽（含往四个方向拖出屏的夹取）、右下角缩放（最小值 320×200 实测；上限 2400×1600 没测到）、黄点最小化、绿点最大化/还原、红点关闭/重开、双击标题栏、2–3 窗口层级与点击置顶、「最小化所有窗口」「关闭所有窗口」「复位窗口位置」。
- **桌面开关**：顶栏「显示」菜单全部 9 项、「App」菜单的「显示 Dock」勾选联动、控制中心 14 个按钮（7 个开关 × 开/关 各一次 + 2 个主题磁贴 + 3 档字体 + Launchpad/Spotlight 按钮）、右键菜单 12 项 + 窗口内 15 项版本 + 3 项窗口操作、壁纸窗口 11 个内置壁纸逐个切换 + 自定义图片 + 恢复默认 + 刷新持久化。
- **无 JS**：5 个 URL 的内容/结构/文案/截图。
- **键鼠**：Esc 关 7 类面板、点外部关 5 类、hoverSwitch、重复点收起、Tab 焦点可见性与顺序（含开窗后 70 次 Tab）、Launchpad 自动聚焦、Ctrl+K / F4。
- **顺带实测到的**：文章页阅读进度条恒 0%（B-17）、开机画面闪烁（C-15）。

### 没覆盖到（如实列出）
1. **缩放上限 2400×1600 没有实测到**：浏览器不向视口外投递 `pointermove`，反复拖只到 1320×867（另一次 1177×757）。所以「缩放到上限」这一条是**不确定**，不是「通过」。
2. **只用了模拟视口，没有真机/真触屏**：全部通过 `Emulation.setDeviceMetricsOverride`（`mobile:false`、DPR 1、隐藏滚动条）完成，**没有真手机、没有 iOS Safari、没有触摸手势**（捏合、滑动惯性、`hover:none` 分支只从 CSS 读到，没实机验证）。也没测横屏。
3. **640–700 之间的宽度没测**（只测了 390/700/1440）。断点两侧各自正常，但 641–699 这段没量。
4. **窄屏下只逐项验证了控制中心**（主题/字体/时钟），**没有在 390 下逐项点击「显示」菜单、右键菜单的 12 项**——它们在 390 下只能通过控制中心间接触达（顶栏那 6 个菜单在窄态没有入口）。这两类的效果验证是在 1440 下做的。
5. **评论组件（`BlogComments`）完全没碰**；`/tags/[tag]` 详情页、`error.vue`（404）也没测。
6. **多标签页 / 多窗口 / 返回前进（bfcache）** 没测；`Esc` 与路由切换的交互只覆盖了「清空桌面切路由自动恢复」这一条源码逻辑，没有逐条实测。
7. **性能类结论只看了一处**：只测了 Spotlight 冷启动与文章页首屏到达时间，没有做全面的性能画像；`sqlite3.wasm` 那 16.5 秒的传输时间**带有本机网络因素**，不能当作线上所有用户的绝对值。
8. **没有验证「修复后」的状态**——本次铁律是只查不修，所以所有结论都只描述**当前线上产物**（本次巡检期间未重新部署；`/_payload.json?_b=2383c2af…` 与 T9 记录一致）。

### 我明确不确定的地方
1. **Spotlight 冷启动的三次读数差异很大**：17309ms（Ctrl+K）、18988ms（右键菜单路径），而**有一次连续轮询约 36 秒始终没出现**（`a-narrow.mjs` 那次）。差异大概率和 `sqlite3.wasm` 的下载速度有关，但我**没有证实**那次是「更慢」还是「失败了」，只能说：**冷启动时用户面对的是「0 反馈」，等待时间从十几秒到几十秒不等**。
2. **`translate-y-[200%]` 那类读数**：Tailwind v4 走 CSS `translate` 属性而非 `transform`，我第一版脚本读 `transform` 得到 `none` 并误判成缺陷；已更正（C-08）。同类「用 `transform`/`matrix` 判断位置」的第三方脚本（包括 `tools/qa.mjs` 里的个别断言）可能也有同样的隐患——这只是**提醒**，我没有去测 `tools/` 里的脚本。
3. **15 项右键菜单最后一项被切 16px**：命中测试在其可见部分（891..900）是**通过**的，所以「点得到/点不到」取决于瞄准精度；我无法确定真人用鼠标是否能稳定点到，只能说**它不再完整可见**。
4. **窄屏禁用窗口拖拽**是源码里写死的取舍（注释说「避免和滑动手势冲突」），我按「预期行为」记；但在窄屏窗口必然超宽的前提下，这个取舍把用户唯一的手动补救手段也拿掉了——**这是取舍还是缺陷，我倾向于算缺陷，但留给你们判定**。
5. **`--window-body-height` 完全失效**（B-17）我是从「inline height 被 `.flex-1` 覆盖」的实测数值（变量 813px vs computed 1989.72px）反推的，没有逐行调试 CSS 优先级，**根因表述可能不完整**；但「容器不可滚 + 进度条恒 0%」是实测事实。

## 5. 本次探针自己犯的错与更正（透明度）

为了保证上面每一条都是真读数，把我踩过的坑列出来——**这些都不是站点的问题**：

| 我的错 | 造成的假象 | 更正方式 | 最终结论 |
| --- | --- | --- | --- |
| 读 `getComputedStyle(dock).transform` 判断 Dock 是否隐藏 | 误判「Dock 自动隐藏不生效」 | Tailwind v4 用 `translate` 属性；改读 `translate` 得 `0px 200%` | 自动隐藏**正常**（C-08） |
| 每次测试都盲目点一次控制中心图标 | 面板其实是 toggle，这次点击把面板**关掉**，后面 `clickLabel` 找不到元素 → 误判「主题/字体/时钟/界面动效/开机动画都不生效」 | 改成 `ensureControl()`（已开就不点）+ localStorage 翻转校验 + 失败重试一次 | 控制中心 **7/7 + 磁贴 + 字体全部正常**（C-10） |
| 用 `window.dispatchEvent(new KeyboardEvent('keydown',{key:'F4'}))` | 监听器挂在 `document` 上，事件派发在 window 不会向下传播 → 误判「Esc 关不掉 Launchpad / 焦点没进搜索框」 | 改用真实 `Input.dispatchKeyEvent` | Launchpad **全部正常**（E-01/E-06/E-10/E-11） |
| 页面都加了「跳过开机动画」的预置脚本 | 该脚本每次导航都会把 `blog_boot_done` 写回 1 → 误判「重播开机动画后登录页不出现 / 卡住」 | 重播相关测试改用**不加预置脚本**的干净页面 | 重播**正常**：788ms 开机画面 → 3880ms 登录页（C-28） |
| 双击用两次 `clickCount=1` | 误判「双击标题栏不会最大化」 | Chromium 需要 `clickCount=2` 才派发 dblclick | 双击**能**最大化（B-08） |
| `clickSel` 里带 `scrollIntoView` | 把壁纸窗口内容滚了 160px，标题栏的「恢复默认」跑出窗口 → 误判「恢复默认点不动」 | 先把 scrollTop 归 0 再点 | 恢复默认**正常**（C-31） |
| 点菜单项时用了「菜单左边框」坐标 / 用超出视口的中心点 | 同一项时灵时不灵 | 改用菜单项自身 rect 中心 | `关于本站` 等项**正常**（C-24） |
| 先 `window.scrollTo` 再同步读 `scrollY` | 站点有 `html{scroll-behavior:smooth}`，同 tick 读到 0 → 误判「文章页不能滚动」 | 滚动后等 1.5s 再读 | 滚动**正常**（A-25） |
| 在 `/blog/` 页面中部右键 | 目标落在 `<a>` 上（源码故意保留浏览器原生右键），菜单压根没弹 → 误判「回到首页不生效」 | 改在最左边缘 (6,500) 右键 | 导航**正常**（C-23） |
