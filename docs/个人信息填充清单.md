### 1.2 `url` 的三个坑（它只错一次就很难救）

1. **线上构建时它会被工作流覆盖**：`.github/workflows/deploy.yml:48` 由 `github.repository_owner` 推导站点地址（`tr` 转小写），第 54 行作为 `NUXT_PUBLIC_SITE_URL` 注入。所以 `shared/site.ts` 里的 `url` **只在本地构建时兜底** —— 而本地构建同样会影响你本地验收的产物，所以它必须一直保持正确。
2. **不要加尾斜杠**。四个 SEO 路由都做了 `.replace(/\/$/,'')` 兜底，但 `app/app.vue:26` 的 canonical **直接把 `siteUrl` 原样写进 `<link rel="canonical">`**，加斜杠会写进一条带尾斜杠的 canonical，与线上真实的根地址不一致。
3. **换域名 / 改仓库名都要联动**：自定义域名要改 `url` + 仓库 Settings → Pages 的 Custom domain，并在构建时覆盖 `NUXT_PUBLIC_SITE_URL`；若仓库名不再是 `<账号>.github.io`（项目站形态），`url` 要变成带子路径的 `https://<账号>.github.io/<repo>`。这些在 `docs/部署.md` §5.2 / §5.9 有完整推演。

## 3. 填之前建议先想清楚的 3 件事

### 3.1 品牌 / 站名：`name` 用什么

现在「我的博客」是模板占位，它出现在：`<title>` 后缀、分享卡片 `og:site_name`、页脚版权、**macOS 菜单栏第一个菜单**、Finder 面包屑、开机登录页、RSS 标题、`llms.txt` 标题。

**命名思路（三个方向）**

1. **网名 + 品类**：`FierceCoder 手记` / `菲斯的笔记` / `Fierce 的代码笔记`
   —— 最容易记，且和 GitHub 号 `Fiercecoder888` 呼应，SEO 上「网名」这个关键词能沉淀到你的域名上。
2. **域名感 / 极简**：`Fierce` / `fierce.dev` / `fierce888`
   —— 菜单栏最干净，`<title>` 最短；缺点是单看没信息量，需要 `description` 补。
3. **一句话态度**：`在浏览器里造小东西` / `写完就跑`
   —— 有辨识度，但当站名用偏长，菜单栏和 `<title>` 容易挤。

**取舍**

- 菜单栏是**单行**的（`TopBar.vue:232`），`<title>` 是 `${文章标题} - ${站名}`，**建议站名 ≤ 12 字符**，否则文章页标题在搜索结果里会被截断。
- 改名会牵连 `tools/verify.mjs:46` 的写死断言（见 §2.3）和 README 两处。
- 名字一旦进 RSS / sitemap / 被搜索引擎收录，改动后旧标题会残留一段时间。**第一次就定下来最好**。

**推荐**：`'FierceCoder 手记'`（网名可检索）+ 用 `description` 补一句「写什么」。

### 3.2 头像：`avatarText` 要不要换成真头像

**现状（已从源码确认）**：头像全部是「一个字」的文字 glyph，共 3 个容器：

| 位置 | 组件:行号 | 容器尺寸 |
|---|---|---|
| 首页名片（桌面 widget） | `app/pages/index.vue:11` | `h-16 w-16` = **64px** |
| 开机 / 登录页 | `app/components/desktop/BootScreen.vue:28` | `h-24 w-24` = **96px** |
| 关于本站窗口 | `app/components/desktop/AboutWindow.vue:5` | `h-12 w-12` = **48px**，且**写死不读字段** |
| 浏览器标签页图标 | `public/favicon.svg:9` | SVG，内嵌「我」 |

**要不要真头像？**

- **只用首字母/单字**（推荐、零改动）：`avatarText: 'F'`，同时把 `favicon.svg` 的「我」换成「F」。缺点：`AboutWindow.vue:5` 仍需手改一次才一致。
- **用真头像**：源码里**没有承载头像图片的 `<img>`**，所以要改上面 3 处模板；图片放 **`public/avatar.png`**（`public/` 下的文件会被原样拷进产物根，无需 import，引用路径就是 `/avatar.png`）；
  尺寸建议 **512×512 PNG**（最大的容器 96px，要覆盖 2x/3x 屏；圆形裁切由容器已有的 `rounded-full` 负责，所以给**正方形原图**即可，透明底也行）；
  同时把 `favicon.svg` 换成姓名首字母版或头像裁切版。
- **取舍**：真人照片提高可信度（尤其你有合作/接活诉求时），代价是把脸和这个 GitHub 账号**永久绑定**、以后很难「匿名重来」；插画/首字母更安全，也符合这个站点「桌面 OS」的调性。

**推荐**：先只改 `avatarText: 'F'` + `favicon.svg`（零代码改动），真头像留到确定要长期运营这个身份时再上。

### 3.3 邮箱与社交：放几个、放哪几个

**结构（已从源码确认）**：`socials` 是 `{ label: string, value: string }[]`，
在 `app/pages/about.vue:44` 被 spread 进 `profile`，在 `about.vue:10-14` 用 `v-for` 渲染成**两列 `dt/dd` 网格**：

- **纯文本，不可点、无图标**（没有 `<a>`、没有 `href`）；
- 顺序 = 数组顺序，排在「昵称 / 坐标 / 方向」之后；
- 两列布局，所以**条数是偶数时排版最整齐**；超过 6 条整块会明显变高。

**最小可用（推荐先上这个）**

```ts
socials: [
  { label: 'GitHub', value: 'github.com/Fiercecoder888' },
  { label: '邮箱', value: 'fiercecoder888 [at] 你的邮箱域名' },
],
```

**完整版（确认会长期更新再加）**

```ts
socials: [
  { label: 'GitHub', value: 'github.com/Fiercecoder888' },
  { label: '邮箱', value: 'hi [at] 你的个人域名' },
  { label: 'X', value: 'x.com/你的handle' },
  { label: '掘金', value: 'juejin.cn/user/你的id' },
  { label: '知乎', value: 'zhihu.com/people/你的id' },
  { label: '个人域名', value: 'fierce.dev' },
],
```

**取舍**

- **GitHub 必放**：它同时是作品集和联系方式，是这个站点最有说服力的一条。
- **邮箱要不要明文？** 站点是纯静态的，关于页的 `dd` 就是**明文 HTML 文本**，爬虫直接抓；而且它**不可点**（无 `mailto:`），所以「防爬」和「方便联系」在这里其实都不占优。
  三个选项：① 用 `xxx [at] domain` 形式（人看得懂、爬虫不好用，推荐）；② 只放 GitHub 不放邮箱；③ 放一个**专门的** `hi@` 地址，将来被刷可以直接弃用。
  不建议用 `you@example.com` 之外的任何「真名邮箱」——真实邮箱一旦进了公开 HTML + 被搜索引擎缓存，很难收回。
- **国内平台（掘金/知乎/即刻）**：放上去等于**公开承诺更新频率**，长期不更新反而是减分项。只放你真的会发内容的。
- **X / Twitter**：如果目标读者里有海外开发者就放，否则可以省。
- **个人域名**：有就放（同时是品牌资产）；没有别硬凑。
- **想让这些变成可点链接**，必须改 `about.vue`（把 `{label,value}` 升级成 `{label,value,href?}`）。这是唯一需要改代码的社交项。

### 第 3 步：肉眼核对 6 个落点

1. `/` —— 名片上的头像字、昵称、方向、tagline/bio；菜单栏第一个菜单文字；页脚 `© 2026 <站名>`；

4. 任意文章页 `<head>` 里 `application/ld+json` 的 `author.name` 已是新作者名（`view-source:` 或开发者工具 Elements 搜索 `BlogPosting`）；
5. `/llms.txt` 首行、`/rss.xml` 的 `<title>`、`/sitemap.xml` 里的域名；
6. 浏览器标签页图标（favicon）里的字。

### 第 4 步：push 后线上复核

