### 3.1 量到的事实

| `sq-ep` | `rgb(0, 92, 197)` | `---` |
| `s4XuR` | `rgb(227, 98, 9)` | `  -` |

`rgb(36, 41, 46)` 就是 `#24292E`（GitHub **Light** 主题的默认前景色），
`rgb(33, 37, 43)` 就是 `#21252B`（代码块背景）。

**WCAG 对比度 ≈ 1.05 : 1**（相对亮度 0.0216 对 0.0182）。正常需要 4.5:1，
1.05:1 等于「几乎完全看不见」——而这 7 个 token 覆盖了代码块的**大部分可见文字**。

### 3.2 根因（三份证据拼出来的）

1. **代码块背景是项目自己写死的深色**：`app/assets/css/main.css:434-441` 的 `.prose-article pre { background: #21252b; color: #abb2bf; }` —— 注意这是**浅色模式**那一段，不是 `.dark` 那一段（`.dark` 的那段把背景改成 `#16181d`）。
2. **token 颜色来自 Nuxt Content 注入的一段内联 `<style>`（1249 字节）**，它用的是 CSS 变量双主题：

   ```css
   html pre.shiki code .sVt8B, html code.shiki .sVt8B { --shiki-default: #24292E; --shiki-dark: #E1E4E8; }
   html .shiki span      { color: var(--shiki-default); ... }   /* ← 默认走浅色调色板 */
   html .dark .shiki span { color: var(--shiki-dark); ... }      /* ← 只有 .dark 才用深色调色板 */
   html.dark .shiki span  { color: var(--shiki-dark); ... }
   ```

   也就是说：**只有 `<html>` 带上 `.dark` 类，token 才会切成深色调色板**（`#E1E4E8` 这种浅灰）。
3. **默认外观是 `light`**：`app/composables/useBlogSettings.ts:36` 的 `DEFAULTS.theme = 'light'`，
   所以首次访客 `<html>` 上永远没有 `.dark`（实测 `htmlClass: ""`、`storedSettings: null`）。

**结论**：浅色外观下 = 深色代码底 + 浅色主题的 token 颜色 = 深字画深底。

### 3.3 反证：深色外观下是好的

我把 `localStorage.blog_settings` 强制写成 `theme: 'dark'` 再刷新：

```json
{
  "htmlClass": "dark",
  "preBg": "rgb(22, 24, 29)",          ← #16181D，.dark 段的背景
  "distinctTokenColors": ["rgb(121, 184, 255)", "rgb(225, 228, 232)", "rgb(255, 171, 112)"],
  "totalTokens": 11,
  "darkTokens": 0                      ← 一个深色 token 都没有了
}
```

**所以这条缺陷只发生在浅色外观 —— 而那恰好是默认外观。**

### 3.4 代码块本身是高亮的，没坏

需要说清楚：**这不是「代码变成纯文本 / markdown 没渲染」。**
Shiki 高亮是生效的：`<pre class="language-ts shiki shiki-themes github-light github-dark">`，
每个 token 有独立 class、独立颜色，`pre code .line{display:block}` 也在生效，
相邻 token 颜色不同（6 种颜色）。4 篇有代码块的文章实测：

| 文章 | `<pre>` 数 | 行/token | 不同颜色数 |
|---|---|---|---|
| `/blog/hello-blog/` | 1 | 9 行 / 11 token | 3 |
| `/blog/nuxt4-content-blog/` | 4 | 18+3+7 行（另有 1 个 `language-text` 无高亮）+ 50/34/12 token | 6 / 6 / 6 |
| `/blog/2024-03-15-vue3响应式踩坑/` | 1 | 2 行 / 15 token | 5 |
| `/blog/带frontmatter的笔记/` | 1 | 2 行 / 18 token | 6 |

（另两篇 `ai-mcp-design-to-code`、`学习笔记-网络基础` 的文章里**没有代码块**，`<pre>` 数为 0，这是内容本身没写围栏代码，不是渲染失败。）

行内代码、表格、引用、链接也都正常渲染（见 `98-article-light.png`）。
