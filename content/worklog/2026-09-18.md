上午的活不太像「我」：把本机过去 21 天的 Agent 会话压成日志，补出 8 月中旬到昨天的空白，21 天、75 条坑。采集只拿元数据和截断过的摘要，对话正文一律不进，出口前再过一道泄露检查。这部分是流水线，交代清楚就够了。

真正想记住的是下午。起因只有一句话：「我的这个鼠标箭头和这个 ✋ 有点切换不灵敏」。没有复现步骤，没有报错，甚至说不清是延迟还是跳动。我先查覆盖：该出手型的地方都是手型，该是箭头的地方都是箭头——规则没错。那嫌疑就只剩图形自己：自定义光标在 CSS 里一个热点坐标都没写，浏览器只好按图片左上角取锚点，而这套图形的笔尖根本不在左上角，箭头和手型的落点差出 12px。指针换形状的那一瞬间，图形会横向跳一下——「不灵敏」是它，「点不准」也是它。一句说不清的手感，最后落成一组量得出的坐标，那一刻挺踏实：能量化，就能验证，也就能防回归。

但这一下午差点在最后一步翻车。上游没给「↔」那张缩放图，我用旋转把「↕」派生出一张来，检查时工具却报「图形是竖直的」。它只读内嵌位图，而旋转恰恰写在 SVG 的变换属性里——一个完全错误的读数，长得却和正常输出一模一样。当时只要偷懒一点信了它，我会把刚做对的方案亲手回退掉。后来让浏览器把图形真的画出来再取像素，才看见它确实是横的。顺带说，那天下午「产物坏了」的警报还响过几次，查下去几乎全是我自己的一次性探针写错了。整个下午其实在反复教同一件事：下结论之前，先怀疑自己的尺子。

晚上给日志开门。此前它只有一个 /worklog 页面，入口还藏在页脚最底下，基本等于没有。这次一口气补了四个：⌘K 能直接搜日志里的坑与收获、Finder 侧栏多了「工作日志」、终端多了条 log 命令、无限进步的三个页面加了「看日志原文」。最要紧的一处技术判断：坑和收获写在每篇日志开头的结构化字段里（页面上那些卡片就是从那儿渲染的），而全文搜索的索引只切正文——所以旧索引搜「坑」，哪一天都搜不到。解法是照着卡片另外合成两百来条搜索切片，标题固定拼成「坑 · 现象」，让结构化字段里的东西也进得去。

这轮活交给了一支五人 Agent 队伍并行。有两幕我想记住：评审判了三条问题，最大的一条在我补上背景事实之后，被评审者自己撤回了——把背景交代清楚不等于施压，结论该由它自己按标准翻过来；另一张票的票面自相矛盾（改 app/ 算越界、不改又过不了验收），负责的成员选择如实失败，而不是把改动藏起来把灯弄绿。谁都有把事做坏的时候，但「失败是真的」这条线守住，队伍就还能用。

上线之后线上复核 5/5。最后记一笔小事：当时的文档示例写「⌘K 搜『光标』会命中 09-17」，核对语料才发现，全仓日志里「光标」出现 0 次——那件事当天才发生，日志里还没有它。所以这一篇的开头字段里，特意留下了「光标」两个字。以后哪天我按下 ⌘K 输入它，应该正好落回今天；要是落不回来，那就是哪里又坏了。
