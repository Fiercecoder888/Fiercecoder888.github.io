## 今天做了什么

今天在给一条自动质量判定链路设计改进路线，并且先把「有多少数据真的能用」这件事盘清楚。

结论是阶段一不动模型：把模型各维度判定、校准指标分数、OCR 结果、感知相似度、目标占比等结构化成特征向量，用逻辑回归 / XGBoost / LightGBM 训一个轻量校准器，输出通过 / 返工 / 驳回的概率；等积累到数千条有效审核记录，再考虑第二阶段基于模型微调。另一条并行线是公开数据集测试，首轮清单已列好，第一件事是排除训练污染。两条线都只做了盘点与清单，没有改文件、也没有下载大型数据。

## 踩的坑与解决

**公开数据集可能已经在模型的训练集里**

拿公开集评测之前先做了一次核对：这个模型的训练集里已经包含 KonIQ、SPAQ、Q-Instruct，直接拿同名样本跑分只会得到虚高的分数。做法是先拿到训练用的样本 JSON，按样本名 / ID 排除全部出现过的样本，只保留未参与训练的保留样本（KonIQ、SPAQ 各取 250–300 张），首轮用 AGIQA-3K、ImageRewardDB 等，并逐条记录样本来源。

**「58 次人工评审」不等于「58 张图片」**

按评审次数统计会高估数据量：部分逻辑 ID 被多轮复用。改成先按逻辑 ID 去重，再只保留能与人工结论可靠绑定的样本（保守口径约 44 张）；同一素材的多版成图与其源图算一组单独列出，不和独立样本混在一起。

**几百条数据该训什么**

几百条记录去微调整个模型，成本高、周期长，还容易把小样本噪声学进去。阶段一改成训一个轻量校准器（逻辑回归 / XGBoost / LightGBM），输入是多路结构化特征，输出是三分类概率——便宜、可解释、迭代快，等数据攒到数千条再考虑微调。

## 今天学到

- 先查训练集再定评测集：用公开数据集评估模型之前，必须确认这些样本没进过它的训练集，否则分数没有意义。
- 「评审次数」不是「样本数」：逻辑 ID 会被多轮复用，统计口径不去重就会高估数据量。
- 只有几百条人工记录时，正确用法是训一个可解释的轻量校准器，而不是动模型本身。
