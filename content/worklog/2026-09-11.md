上午到下午主要干了一件事：**把「所有 Agent 干过的活都能自动变成工作日志的原料」做成真的**，顺带修掉一个入口问题。

一是入口。有人问「无限进步那个栏目在哪里」，一 grep 才发现 `/progress` 在整站页面上没有任何文本链接，只能从 Dock、菜单、Launchpad 三个按钮进，而 390px 窄屏下 Dock 还得横向滚动才点得到。页脚改成完整导航，窄屏 Dock 改成两行 6+5，实测 390×844 下 scrollWidth 从 700 降到 374，11 个图标全部落进视口、不用横滑，宽屏 52px 单行的外观逐字未变。

二是采集。新增 `scripts/agent-sessions.mjs`（930 行）：读本机 Codex / Claude Code / DSH 三家的会话记录，按「日期 + 工作目录」筛出跟本仓库相关的会话，只提取元数据与截断摘要（首条需求 ≤80 字、最后结论 ≤120 字、工具调用次数、失败重试次数、有无代码改动、子代理数），对话正文、思考链、工具入参出参、命令输出一律不进。这一步卡了两个坑：仓库嵌在工作区里导致一条都采不到，以及 DSH 的会话文件是多帧 zstd。

三是去噪与归属。会话线索每 Agent 最多 3 条、合计最多 5 条，排序按「有代码改动 > 失败重试 > 时长」，子代理会话合并进根会话（一次派 3 个子代理，4 条变 1 条）；提交侧只让 feat/fix/perf/refactor 单独成行，其余折叠成一行摘要。归属优先读提交 trailer，读不到才用会话记录推断，日志新增 `agents[]` 和每条坑的 `pitfalls[].agent` 两个粒度。

四是呈现。新增 `app/utils/agent.ts` 固定配色，日志详情页显示「今天参与」与每条坑的 Agent 徽章，坑库页加「按 Agent」筛选，统计页加「Agent 参与分布」；字段缺失时不显示徽章、不露 `undefined`。

下午换了个方向：**黑盒拆了一套招聘系统**，并做了同类开源项目的调研。方法上分三步——先拿契约（15 个路由组、约 50 个端点），再从控制台前端 JS 里把状态机捞出来（19 个状态），最后从一份审查报告的 PDF 附录反推出八个维度的评分权重表；全程只发只读请求，不碰任何写接口。调研部分派了子代理并行做，头部那条结论我自己复核了。

傍晚又换了一次方向：**评审一套制造订单全链的业务流程图**，并调研车间执行与成本核算该怎么存。评审的做法是拿「实际系统 + 实测证据」去对图：先定位系统的验收线在哪一步（图上恰好缺了那一段），再逐条标出画错的地方（未审核的识别结果和已定版的标准数据被画成了同一个库）、缺的节点（接收与登记、文件分类、历史模板检索），以及图里完全没有的三个横向层（人工 Gate、证据/审计、只读问答）——这三层不画出来，看图的人会以为这是一条全自动流水线，而它实际上是「AI 只提案，事实与副作用由确定性代码加人工 Gate 兜底」。调研那边对标了主流 ERP 的存储设计（报工为什么要「明细 + 累计」两张表、工序损耗为什么要逐序存、联产品和副产品为什么是两件事、追溯为什么先做不可变流水而不是物化表），并把几份国际标准（ISA-95 / B2MML / IEC 62264 / OPC UA）翻了一遍，逐条标了证据等级。

## 踩的坑与解决

**入口做了却没人找得到**（约 1 小时）
用户问「栏目在哪里」时才 grep 出来：`/progress` 只能从 Dock、菜单、Launchpad 三个按钮进，页面上没有任何文本链接指向它，而窄屏下 Dock 还要横滑才点得到。页脚改成完整导航，窄屏 Dock 改成两行 6+5，390×844 实测 scrollWidth 700 → 374，11 个图标全在视口内。

**会话采集一条都采不到**（约 40 分钟）
Agent 启动时的工作目录是仓库的**上一层工作区**，仓库根却是它下面的子目录，只认仓库根匹配就全空。默认把父目录也算相关之后正常。一个仓库住在别人的目录里，路径匹配不能只认最精确的那个。

**压缩流是多帧的**（约 1 小时）
按常规方式解压 DSH 的会话文件只能拿到第一帧，后面整段丢失，一开始还误以为是会话记录本身不全。改成扫魔数逐帧解压才对。凡是压缩流套压缩流的格式，先假设多帧。

**改尺寸压住了别人**（约 20 分钟）
窄屏 Dock 变两行后整体变高，压住页脚最后一行。把 pb-28 改成 pb-48 sm:pb-28，宽屏外观未变。响应式里改一处尺寸，得连带看它下游压住了谁。

**把解码假象当成了结论**（约 30 分钟）
黑盒取证时我一度认定「目标有两套静态挂载、内容还不一样」，其实是我读响应用了会放大字符计数的解码方式——同一个文件按两种编码读出来的长度不同。换回原始字节做 SHA256 比对，两边完全一致，推断当场被证伪。凡是「看起来不对劲」的读数，先用另一种方式验一遍。

**照着图的边界看，漏掉了验收线**（约 1 小时）
评审流程图时我一开始跟着图走，而图到「采购执行」就结束了——系统的验收线在后面那一段（排程 / 派工 / 报工），那正是当时最薄弱、靠人工补得最多的一环（实测里它因为缺定版审批引用和标准工时而报错）。先问「哪一步算完成、算被验收」，再用实测证据反查图，视野才对上。

**未审核的识别结果被画进了标准库**（约 40 分钟）
图上两处都写「标准库」，于是「AI 识别出来的候选」和「人工审定后的定版」看起来是同一个库——按这个图实现，识别结果就能直接驱动业务了。正确画法是两段：候选库（带证据与置信度，不驱动业务）→ 人工 Gate → 定版库（带修订号与来源引用）。

**「现有库存」几个字掩盖了最费劲的部分**（约 40 分钟）
缺口计算写成「订单量 × 用量 − 现有库存 − 在途」看着没问题，但可用量还得扣锁定量和不合格品，并且要带 as-of 时点、仓库、批次、质检状态。图上出现的每一个汇总名词，都得追问它背后拆成了哪几列。

**字段清单里混进了第三方镜像**（约 30 分钟）
调研对标系统的存储设计时，抓到的字段有相当一部分来自第三方镜像字典——那家厂商官方从不公开表名和字段名，我一开始没区分来源，把镜像资料和官方资料排在了一起。改成逐条标证据等级（一手 / 镜像 / 未验证）之后，哪些能当事实用才清楚。

## 今天学到

- 入口存在不等于可发现：功能做完、页面能访问，但整站没有文本链接指向它，用户就是找不到。
- 采集原料的第一件事是划隐私边界：只取元数据与截断摘要，正文、思考链、工具入参出参一律不进。
- 归属要靠显式标记兜底（提交 trailer），推断只能当补充；日志级和单条坑级两种粒度都要留。
- 黑盒摸一套系统，契约比界面可靠得多：界面只暴露它想让你看到的。
- LLM 打分的方差比功能多少更致命——同一份材料跑出很大区间，排行榜就是噪声。这类系统的门槛不是能不能跑起来，而是准不准、以及人愿不愿意信它。
- 子代理的调研结论默认不可直接采信，头部那条必须自己复核；复核不了的要显式标成未核实。
- 评审别人画的流程图，先问「哪一步算完成、算被验收」——图的边界往往不是系统的边界。
- 凡是 AI 参与的链路，图上必须显式画出人工 Gate、证据 / 审计、只读问答这三层，否则一定被读成全自动；真实的边界是「AI 只提案，事实与副作用由确定性代码加人工 Gate 兜底」。
- 汇总名词是评审的重点：「现有库存」这类词背后通常藏着时点、批次、状态、锁定量四件事。
- 调研外部系统怎么存数据，每条结论都要标证据等级（一手 / 镜像 / 未验证）；官方不公开表结构的系统尤其如此，否则推断会混进事实。
